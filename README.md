# حضور+ (HozorPlus)

سیستم جامع مدیریت حضور و غیاب تحت وب — با رابط کاربری کاملاً فارسی و راست‌به‌چپ.

جانشین مدرنِ نرم‌افزارهای دسکتاپی قدیمی: بدون نیاز به نصب روی تک‌تک سیستم‌ها، از هر مرورگری (دسکتاپ و موبایل) قابل استفاده است و همزمان دستگاه‌های اثرانگشت ZKTeco را نیز پشتیبانی می‌کند.

### اتصال دستگاه NP756+ (نوین پرداز)

از v1.4.0 دو مسیر ارتباطی برای دستگاه‌های NP پشتیبانی می‌شود که برای هر دستگاه **صریح** انتخاب می‌شود (هرگز از روی پورت حدس زده نمی‌شود):

| | FKAttend (SDK رسمی) | SBXPC (مسیر قدیمی) |
| --- | --- | --- |
| روش | سرویس داخلی ۳۲ بیتی + `FK623Attend.dll` رسمی | پروتکل باینری مستقیم |
| پورت پیش‌فرض | **۴۲۳۸** (قابل تغییر) | ۵۰۰۵ |
| وضعیت | مسیر تأییدشدهٔ NP756+ (اتصال موفق ثبت‌شده) | حفظ‌شده و کاری |
| تنظیمات کاربر | فقط IP، پورت، رمز عددی | IP، پورت، رمز شبکه |
| سرویس ارتباط | **خودکار و پنهان** توسط خود نرم‌افزار (v1.5.0) | — |

**FKAttend (پیشنهادی برای NP756+) — یکپارچه و بدون کار فنی (v1.5.1):**

1. از v1.5.1، DLLهای SDK (۷ فایل تأییدشده: `FK623Attend.dll` + `FKAttend.dll` + ۵ DLL همراه) **همراه خود بستهٔ نصب** در `tools\fkattend-bridge\bin` قرار دارند — هیچ کپی دستی لازم نیست. کل وابستگی‌ها با تحلیل PE import فایل‌ها تأیید شده و هش SHA-256 آن‌ها در `tools/fkattend-bridge/bin/README-DLL.txt` ثبت است.
2. در حضور+ دستگاه را با پروتکل «FKAttend» ثبت کنید: **فقط** نام، سریال، IP دستگاه، پورت (پیش‌فرض ۴۲۳۸) و در صورت وجود «رمز شبکه».
3. «تست اتصال» را بزنید. همین.

سرویس ارتباط دستگاه (Bridge x86) از این نسخه **خودش را خود نرم‌افزار اجرا و مدیریت می‌کند**: مخفی و بدون هیچ پنجره‌ای بالا می‌آید، در صورت از کار افتادن راه‌اندازی مجدد می‌شود، هنگام بستن نرم‌افزار تمیز متوقف می‌شود و توکن آن **خودکار تولید** و فقط در حافظهٔ فرآیند نگه داشته می‌شود. کاربر هیچ توکنی نمی‌بیند، کپی نمی‌کند و هیچ BAT/PowerShell ای اجرا نمی‌کند. جزئیات معماری: `docs/BRIDGE-SUPERVISION.md`.

- «تست اتصال» فقط وضعیت/زمان پاسخ را می‌خواند و چیزی روی دستگاه تغییر نمی‌دهد؛ «دانلود ترددها» کل حافظه را می‌خواند و فقط رکوردهای جدید را ذخیره می‌کند (idempotent — دریافت تکراری هرگز رکورد تکراری نمی‌سازد).
- جزئیات قرارداد JSON سرویس: `tools/fkattend-bridge/CONTRACT.md` · اعتبارسنجی روی دستگاه واقعی: `tools/fkattend-bridge/CHECKLIST-WINDOWS.md`
- اگر DLLها به هر دلیل (مثلاً قرنطینهٔ آنتی‌ویروس) حذف شده باشند، نرم‌افزار پیام روشن می‌دهد که بسته را دوباره باز/نصب کنید؛ چیز دیگری خراب نمی‌شود.

دستگاه **فقط خوانده می‌شود**: سرویس ارتباط هیچ فرمان تغییر/حذف/خالی‌سازی روی دستگاه ارسال نمی‌کند و مسیر بازگشتی همیشه باز است. `START-BRIDGE.bat` فقط ابزار عیب‌یابی دستی باقی مانده است و در استفادهٔ عادی لازم نیست.

**SBXPC (قدیمی):** روی منوی دستگاه ← تنظیمات ← ارتباط، «آدرس سرور» را IP همین سیستم و پورت ۵۰۰۵ بگذارید (پوش لحظه‌ای) و IP دستگاه را در پرونده وارد کنید (دانلود مستقیم).

### دریافت خودکار و شبه‌بی‌درنگ (v1.4.0)

در تنظیمات هر دستگاه مستقل از پروتکل: «دریافت خودکار» (Scheduler در **سرور** اجرا می‌شود — نه مرورگر؛ با ری‌استارت سرور ادامه می‌یابد و از دیتابیس خوانده می‌شود) و «دریافت شبه‌بی‌درنگ (Polling)» با فاصلهٔ قابل تنظیم (پیش‌فرض ۳۰ ثانیه؛ برچسب صادقانه: Polling است، نه Real Push — برای پوش واقعی RTLOG تحقیق فنی جداگانه لازم است). تحقیق فنی کامل قابلیت‌های FKAttend (دسته‌بندی A/B/C) در `docs/FKATTEND-CAPABILITIES.md` ثبت شده است. هر دو مسیر از همان قفل per-device و داینوپهٔ اثر انگشت (RawPunch) عبور می‌کنند؛ هم‌زمانی یا تکرار Sync هرگز رکورد تکراری نمی‌سازد.

### عیب‌یابی اتصال

- **«سریال ناشناس» در تاریخچه عملیات** → دستگاهی پیام فرستاده که سریالش ثبت نشده؛ با همان سریال دستگاه اضافه کنید.
- **هیچ پیامی نمی‌رسد** → آدرس سرور/پورت روی منوی دستگاه، فایروال و در یک شبکه بودن را بررسی کنید.
- **پیام می‌رسد ولی تردد ثبت نمی‌شود** → «شناسه روی دستگاه» پرسنل را مطابق UserID دستگاه تنظیم کنید (در تاریخچه عملیات دقیق دلیل آمده).

## 🖥️ نصب سریع روی ویندوز

> راهنمای تصویری نداره ولی واقعاً **دو دابل‌کلیک** بیشتر لازم نیست!

1. فایل `HozorPlus-v1.0.0-Windows-Setup.zip` را از بخش [Releases](../../releases) دانلود و استخراج کنید (پیشنهاد: مسیری کوتاه و بدون فاصله مثل `C:\HozorPlus`)
2. روی **`INSTALL.bat`** دابل‌کلیک کنید — این اسکریپت به‌ترتیب:
   - نبود Node.js را بررسی و در صورت نیاز با `winget` نصب می‌کند
   - پکیج‌ها را نصب می‌کند (`npm install`)
   - دیتابیس SQLite را می‌سازد و دادهٔ نمونهٔ فارسی را بارگذاری می‌کند
   - بیلد production را انجام می‌دهد
3. روی **`START.bat`** دابل‌کلیک کنید — مرورگر روی `http://localhost:3000` باز می‌شود ✅
4. برای توقف: پنجرهٔ سرور را ببندید یا `STOP.bat` را اجرا کنید

**پیش‌نیازها:** ویندوز ۱۰/۱۱ ×۶۴، اینترنت فقط برای مرحلهٔ نصب، و Node.js نسخهٔ ۲۰ به بالا (اسکریپت خودش نصب می‌کند).

**دسترسی از سایر سیستم‌های شبکه:** اگر ویندوز فایروال اجازهٔ دسترسی داد (Allow access)، دیگر کارکنان با آدرس `http://<IP-سیستم>:3000` می‌توانند وارد شوند.

## 🧑‍💻 راه‌اندازی برای توسعه‌دهندگان (هر سیستم‌عاملی)

```bash
git clone -b develop https://github.com/P3D4AM/novin-rahzan.git
cd novin-rahzan
npm install
cp .env.example .env            # مسیر دیتابیس را تنظیم کنید
npx prisma generate
npx prisma db push
```


بیلد production:

```bash
npm run build
npm start
```

## 🗄️ دیتابیس

به‌صورت پیش‌فرض **SQLite** است تا نصب بدون تنظیم باشد. برای استقرار سازمانی روی **PostgreSQL**:

1. در `prisma/schema.prisma` مقدار `provider` را به `"postgresql"` تغییر دهید
2. در `.env` رشتهٔ اتصال Postgres را قرار دهید
3. `npx prisma db push && npm run seed` را اجرا کنید

بقیهٔ کد به‌کلی قابل حمل است (ORM بدون ویژگی وابسته به دیتابیس خاص).

### لایهٔ صحت دادهٔ ترددها (v1.3.0 — RawPunch)

از v1.3.0 هر ترددی که از دستگاه (یا فایل مرجع) وارد می‌شود، ابتدا در جدول مستقل `RawPunch` ذخیره می‌شود — بدون وابستگی اجباری به تعریف پرسنل:

- **بدون حذف:** رکوردهای بدون تطبیق با وضعیت `UNMATCHED` نگه داشته می‌شوند و با افزودن/ویرایش پرسنل بعداً به‌طور خودکار تطبیق می‌خورند (`rematchRawPunches`).
- **بدون تکرار:** هویت رکورد = سریال دستگاه + پروتکل + شمارهٔ ثبت + اثر انگشت خام (SHA-256 روی مقادیر خام) + اندیس هم‌زمانی؛ یعنی رویدادهای هم‌ثانیهٔ یکسان هم بدون ادغام ذخیره می‌شوند.
- **بدون حدس:** مقادیر خام in/out و verify عیناً ذخیره می‌شوند و جهت تردد تا تأیید معنای رسمی آن‌ها `UNKNOWN` می‌ماند؛ ساعت خام دستگاه (`punchTimeRaw`) کنار زمان UTC نگه داشته می‌شود.
- **نشانگر امن:** `Device.rawCursorAt` فقط پس از ذخیرهٔ امن همان بسته جلو می‌رود (داخل همان تراکنش)؛ تاریخچهٔ هر اجرا در `DeviceSyncRun` ثبت می‌شود (شامل تعداد Retry).
- **امنیت رمز:** رمز «شبکه» دستگاه دیگر در هیچ پاسخ API، لاگ یا پیام خطایی ظاهر نمی‌شود.

مهاجرت دیتابیس **افزایشی و قابل بازگشت** است: نصب‌های جدید با `prisma db push` (مرحلهٔ ۴ نصب) خودکار به‌روز می‌شوند و برای نصب‌های موجود:

```bash
node scripts/migrate-v1.3.0-phase1.mjs            # اعمال (ایمن و تکرارپذیر)
node scripts/migrate-v1.3.0-phase1.mjs status     # وضعیت فعلی
node scripts/migrate-v1.3.0-phase1.mjs down --confirm   # بازگشت (جدول‌های جدید را حذف می‌کند)
```

### اصلاحات بازبینی فاز ۱ (v1.3.1)

پس از بازبینی کدِ فاز ۱، این نسخه شش ایراد تأییدشده را اصلاح می‌کند (بدون تغییر رفتار SBXPC/EBIO و بدون حذف هیچ داده‌ای؛ مهاجرت افزایشی و قابل بازگشت):

- **تطبیق پرسنل بدون حدس:** شماره‌های ثبت به‌صورت رشتهٔ دقیق (حفظ صفرهای ابتدایی) با دو نمایهٔ جداگانهٔ `deviceUserId` و `personnelCode` مقایسه می‌شوند؛ برخورد یا ابهام هرگز خودکار انتساب نمی‌شود و رکورد با توضیح `matchNote` (قابل مشاهده توسط مدیر در `GET /api/raw-punches?ambiguous=1`) تطبیق‌نخورده می‌ماند.
- **بازمحاسبهٔ حضور به‌ازای هر (شخص، روز):** روزِ همان تردد بازمحاسبه می‌شود (نه maxPunchTime سراسری)؛ خطای بازمحاسبه بی‌صدا بلعیده نمی‌شود — وضعیت اجرا «ناقص» (PARTIAL) ثبت می‌شود و `retrySyncRunRecalcs` بدون دریافت مجدد از دستگاه آن را ترمیم می‌کند.
- **تطبیق مجدد اتمی و قابل حسابرسی:** به‌روزرسانی نگاشت + پروجکشن + رکورد AuditLog در «یک» تراکنش؛ شکست بین این مراحل همه‌چیز را برمی‌گرداند و رکورد قابل تکرارِ دوباره باقی می‌ماند.
- **قرنطینهٔ رکوردهای خراب:** هیچ رکوردی بی‌ردپا حذف نمی‌شود — رکوردهای با مهر زمانی نامعتبر با payload خام و دلیل در `RejectedRecord` نگه داشته می‌شوند؛ شمارش کامل (seen = inWindow + rejected + outOfWindow) در `DeviceSyncRun` ثبت می‌شود و اجرای دارای رکورد قرنطینه‌شدهٔ جدید هرگز SUCCESS تمیز گزارش نمی‌شود (PARTIAL).
- **قفل همگام‌سازی مبتنی بر پایگاه‌داده:** قفل per-device در جدول `DeviceSyncLock` با lease انقضا (بازیابی پس از کرش) — محافظت بین چند فرآیند سرور؛ محدودیت یکتایی پایگاه‌داده همچنان خط آخر دفاع در برابر تکراری‌هاست.
- **مرز صادقانهٔ رمز دستگاه در حالت سکون:** رمز «شبکه» به‌صورت پیش‌فرض همچنان عددی رمز‌نشده در SQLite است (محدودیت مستندشده). محافظت اختیاری DPAPI ویندوز با `scripts/protect-device-secrets.ts` — جزئیات مرز محافظت و الزامات بازیابی در [`docs/SECURITY-device-password-at-rest.md`](./docs/SECURITY-device-password-at-rest.md).

برای نصب‌های موجود (زنجیرهٔ کامل ارتقا، به‌ترتیب):


## English summary

**HozorPlus (حضور+)** is a full-featured, RTL-first Persian web attendance system built with Next.js 16, TypeScript, Tailwind CSS 4 + shadcn/ui, Prisma (SQLite default, PostgreSQL-ready) and socket.io realtime.

- **Windows one-click install:** extract the release zip → `INSTALL.bat` → `START.bat` → <http://localhost:3000> (`admin` / `admin123`)
- Modules: personnel, shifts (fixed/split/overnight/rotations), attendance engine, web self-check-in with geolocation, PIN/QR kiosk, ZKTeco device sync (TCP/UDP 4370), Excel/CSV import, leave & overtime workflows, smart notifications, Persian AI assistant, live dashboard, monthly reports with Excel export, 4-level RBAC.

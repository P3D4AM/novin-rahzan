# Bridge Supervision — معماری مدیریت خودکار FKAttend (v1.5.0)

> این سند تصمیم معماری فاز «یکپارچه‌سازی اتصال NP756+» است: حذف اجرای دستی
> Bridge، پنجرهٔ CMD، کپی/ورود توکن و مدیریت فرایند توسط خود HozorPlus.

## واقعیت استقرار (مبنای تصمیم)

HozorPlus طبق `INSTALL.bat`/`START.bat` **روی همان ویندوزی اجرا می‌شود که دستگاه
از طریق شبکه به آن دسترسی دارد**:

```
START.bat → node scripts/start-windows.js (x64)
            ├─ mini-services/realtime (:3003)
            └─ .next/standalone/server.js (:3000)  ← مرورگر همین سیستم/شبکه
```

پس پردازش Node سرور می‌تواند Bridge را به‌عنوان **child process مخفی** مدیریت
کند. چون «چرخهٔ عمر نرم‌افزار» همان «چرخهٔ عمر START.bat» است، نیازی به Windows
Service جدا نیست (نصب سرویس نیازمند دسترسی مدیر، نصب‌کنندهٔ جدا و بازیابی در
به‌روزرسانی است — پیچیدگی غیرضروری برای استقرار فعلی).

**دسترسی از مرورگرِ سیستم راه‌دور:** مرورگر هرگز DLL/PowerShell را اجرا نمی‌کند؛
نرم‌افزار در همهٔ حالت‌ها از طریق Backend خودش با Bridge حرف می‌زند. استقرار
سرور روی غیر ویندوز (میزبان راه دور) برای FKATTEND پشتیبانی نمی‌شود و در خطای
وضعیت به‌صراحت اعلام می‌شود.

## تصمیم معماری

```
Next.js server (x64 Node) ── supervisor ──> child: SysWOW64 powershell.exe (32-bit)
     │  localhost HTTP + token (env)               └─ FK623Attend.dll → NP756+ :4238
     └─ مرورگر فقط با Next.js حرف می‌زند — هیچ نام/توکن/پورت Bridge را نمی‌بیند
```

* `src/lib/bridge-supervisor.ts` — تنها مسئول چرخهٔ عمر Bridge:
  start مخفی (`windowsHide`)، بررسی readiness روی `GET /ping`، صحت‌سنجی
  `/health` با توکن، انتخاب پورت با fallback (8765..8775)، تشخیص exit ناگهانی و
  restart با backoff، توقف تمیز (`POST /shutdown` + `taskkill /T /F` fallback)،
  قلاب‌های `exit/SIGINT/SIGTERM` برای عدم باقی‌ماندن پردازش یتیم.
* تک‌نمونه بودن: supervisor خودش singleton است روی `globalThis`؛ اگر پورت
  پیش‌فرض اشغال باشد (نمونهٔ قدیمی/غریب)، child جدید نمی‌تواند bind کند، با کد
  خروج 3 خارج می‌شود و supervisor پورت بعدی را امتحان می‌کند.
* DLL: `FK623Attend.dll` (امضاهای تأییدشدهٔ دستگاه واقعی — بدون workCode،
  `FK_DisConnect`، `LoadGeneralLogData(handle, readMark)`). مسیر جست‌وجو:
  `FKBRIDGE_DLLDIR` → `<نصب>\tools\fkattend-bridge\bin\` →
  `<نصب>\tools\fkattend-bridge\`. مسیر کامپیوتر کاربر هرگز hardcode نمی‌شود.

## توکن — تولید و انتقال

* تولید: `crypto.randomBytes(32).toString('hex')` در هر راه‌اندازی supervisor.
* انتقال به Bridge فقط با **متغیر محیطی `FKBRIDGE_TOKEN`** — نه argv (پس در
  فهرست پروسه‌ها و log دیده نمی‌شود)، نه فایل، نه شبکه.
* Frontend هرگز آن را دریافت نمی‌کند (تنها عضو امنیتی که به UI می‌رود، وضعیت
  «در حال اجرا» است). مقدار هرگز در URL/پیام خطا/log ثبت نمی‌شود.
* احراز هویت Bridge با هدر سفارشی `x-bridge-token` روی هر endpoint (به‌جز
  `/ping` که فقط `{"ok":true}` برمی‌گرداند). هدر سفارشی یعنی preflight اجباری
  مرورگر → درخواست cross-site (CSRF از وب‌سایت‌های دیگر) بدون پاسخ CORS مسدود
  می‌شود. Listener فقط روی `127.0.0.1` bind می‌شود.
* هماهنگی پس از restart: توکن جدید دوباره تولید/منتقل می‌شود — هیچ حالت
  «توکن ناسازگار» باقی نمی‌ماند چون هر نمونه Bridge با توکن همان supervisor
  راه‌اندازی شده است.

## رفتار مورد انتظار کاربر

* ورود به بخش دستگاه‌ها → `GET /api/devices?bridge=1` وضعیت سرویس را نشان
  می‌دهد (بدون spawn — فقط وضعیت).
* «تست اتصال» / «دریافت تردد» → provider خودش `ensureBridge()` را صدا می‌زند؛
  اگر Bridge نباشد، بالا آورده می‌شود؛ اگر crash کرده باشد، restart می‌شود.
* خطاها فارسی و قابل‌اقدام‌اند: DLL نبود (v1.5.1: DLLها همراه بسته‌اند؛ یعنی
  نصب خراب یا قرنطینهٔ آنتی‌ویروس → «بسته را دوباره باز کنید»)؛ PowerShell
  32-bit نبود؛ دستگاه خاموش (کد FK_ConnectNet)؛ غیر-Windows.

## محدودیت‌ها (صادقانه)

* probe سریال/زمان (`FK_GetSerialNumber/GetDeviceTime`) عمدتاً خاموش است
  (امضاهایش جزو مجموعهٔ تأییدشده نیستند؛ خرابی آن‌ها در آزمایش واقعی دیده شد
  و مانع خواندن تردد نبود). فاز مستقل بررسی می‌شود.
* اعتبارسنجی سخت‌افزاری نهایی (۲۹۴۷ رکورد / endCode -7 / بازیابی قطع شبکه)
  طبق `tools/fkattend-bridge/CHECKLIST-WINDOWS.md` روی کامپیوتر کاربر انجام
  می‌شود؛ ادعای سخت‌افزاری در این مرحنه مطرح نیست.
* `START-BRIDGE.bat` فقط ابزار عیب‌یابی دستی باقی می‌ماند — مسیر عادی کاربر
  دیگر هرگز به آن نیاز ندارد.

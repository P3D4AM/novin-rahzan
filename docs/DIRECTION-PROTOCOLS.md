# جهت ورود/خروج (IN/OUT) — وضعیت هر پروتکل و سیاست نمایش

> فاز ۲، بند ۷ (v1.8.0-dev). مشکل گزارش‌شده: «در جدول ترددها، نوع رکوردها تقریباً همگی «خودکار» نمایش داده می‌شوند.»

## ریشهٔ نمایش «خودکار»

مقدار `AUTO` واژگان قدیمی برای «جهت نامشخص» است: رکورد از منبع خود جهت IN/OUT نگرفته است. نمایش قبلی («خودکار») گمراه‌کننده بود؛ حالا همان مقدار با برچسب صادقانهٔ **«نامشخص»** و راهنمای شفاف نمایش داده می‌شود (اگر پروتکل جهت را گزارش نکرده باشد، جهت ساختگی تولید نمی‌شود — قاعدهٔ v1.3.0 fix 4).

محاسبات بدون جهت ذخیره‌شده درست کار می‌کند: لایهٔ جفت‌بندی (`src/lib/pairing.ts`) برای روزهای بدون جهت، جفت‌بندی مکانی تعیین‌پذیر (IN بازکننده/OUT بستنی) انجام می‌دهد — نتیجهٔ محاسبه صحیح است اما جهت ذخیره‌شده را «نمی‌سازد».

## رویهٔ تأیید آیندهٔ FKATTEND (بدون حدس)

برای فعال‌کردن نگاشت `inOutMode` → IN/OUT نیازمند یکی از این دو است:

1. **سند رسمی سازنده** برای `FK_GetGeneralLogData` (معنی `inOutMode`) — این SDK عمومی ایندکس نشده و تا امروز در دسترس نبوده؛ یا
2. **نمونهٔ دادهٔ واقعی تأییدشده**: یک نفر روی NP756+ ثبت‌های ورود و خروج صریح (کلید حالت در دستگاه، اگر موجود است) انجام دهد و مقادیر `inOutMode` متناظر در تب «ترددهای خام دستگاه» ثبت و مقایسه شود. اگر و فقط اگر الگو پایدار و با سند سازنده ناسازگار نباشد، نگاشت در `src/lib/fkattend.ts` با تست داده‌محور فعال می‌شود.

تا آن زمان مقدار خام برای ممیزی حفظ می‌شود و جهت «نامشخص» می‌ماند — چون تولید جهت ساختگی ممنوع است (بند ۷: «نباید جهت ساختگی تولید شود؛ مقادیر خام باید برای ممیزی حفظ شوند»).

## نمایش در UI

- تب «ترددها (عملیاتی)»: ستون «نوع» → ورود / خروج / **نامشخص** (با راهنمای دلیل).
- تب «ترددهای خام دستگاه»: مقادیر خام کامل (`inOutModeRaw`, `verifyModeRaw`, `workCode`, `punchTimeRaw`, پروتکل) نمایش داده می‌شوند — ابزار ممیزی.
- فرم ثبت دستی: «نامشخص (بدون جهت)» / ورود / خروج.
